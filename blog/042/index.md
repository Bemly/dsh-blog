sunday 的实操技巧：**本机 443 端口被占用，又不想换服务的端口，借助 Cloudflare 的 Origin Rules 把非标准端口映射到标准端口，实现"域名不加端口号访问"**。归纳要点：

- **思路**：服务监听非标准端口（示例 nginx 开 8443），域名托管在 Cloudflare 并开启橙色小云朵（代理模式），再在 CF 规则里把"该主机名的目标端口"改写为 8443，这样访问 `test.example.xyz` 时 CF 自动转发到源站 8443，URL 不用带端口。
- **操作步骤**：① 域名托管在 CF、A 记录指向服务器 IP、打开代理；② CF 控制台 → 规则 → Origin Rules（源站规则）→ 新建规则，选择"自定义筛选表达式：主机名等于你的主机名"，目标端口填 8443，保存。
- **限制**：非标准端口代理会失去 CF 的缓存加速（页面加速没有了）；使用 HTTPS 访问非标准端口且开了小云朵时，需要在 SSL 设置里做相应配置；CF 小云朵支持的目标端口有固定列表（HTTP：80/8080/8880/2052/2082/2086/2095；HTTPS：443/2053/2083/2087/2096/8443）。
- **注意**：8080/8880/2052/2083/2087/2095/2096/8443 等端口 CF 支持但默认禁用缓存。

价值点：这是"443 被占 + 不想改端口 + 想用标准 URL"场景下的轻量解法，不需要 Spectrum 付费功能，普通免费 CF 的 Origin Rules 即可实现端口改写，适合自建服务/家庭 NAS 反代场景。

## 正文

443端口被占用，但是又不想换这个服务的端口，可以利用 cloudflare 代理来实现域名不加端口访问。

### 1. 域名要托管在 cloudflare，然后域名解析到你的服务器IP，打开橙色小云朵

![域名解析与橙色小云朵设置截图](images/i01-screenshot-20240118.avif)

比如你 nginx 上启动一个 8443 端口的代理，配置如下：

```nginx
server {
  # 如果有资源，建议使用 https + http2，配合按需加载可以获得更好的体验
  listen 8443 ssl http2;
  ...
}
```

ssl 证书可以用 CF 的。

### 2. 在 cloudflare 的规则里设置流量目标端口

![Cloudflare Origin Rules 设置界面](images/i02-origin-rules.avif)

比如我 nginx 设置的 8443，在这里选择 **自定义筛选表达式—— 主机名 等于 <填写你的主机名>**，然后 **目标端口 填写 8443**，保存即可。

这样就可以通过 `test.example.xyz` 不加端口访问你部署的服务了，但是你的网站用不了 CF 的加速了。

顺便提一下，cloudflare 开启小云朵后支持的目标端口：

- **Cloudflare 支持的 HTTP 端口**：80、8080、8880、2052、2082、2086、2095
- **Cloudflare 支持的 HTTPS 端口**：443、2053、2083、2087、2096、8443
- **Cloudflare 支持的端口，但是禁用缓存**：意思是你的网站没有加速功能了

⚠️ 注意：使用 https 访问非标准端口，且是开启了小云朵的，需要在 SSL 那里设置。
